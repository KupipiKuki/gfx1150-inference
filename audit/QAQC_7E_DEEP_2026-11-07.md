## 2. Event-graph audit (line by line, `attention.hip`)

- ✅ Entry: `hipMemcpyAsync(d_x, d_norm_w)` on copy stream → `inputs_done` recorded → compute waits `inputs_done` before rmsnorm. `norm_consumed` recorded after the rmsnorm launch; the ffn-norm copy into the reused `d_norm_w` waits `norm_consumed` on the copy stream first — the d_norm_w reuse race is closed.
- ✅ Per projection `p` (slot `p%2`): copy stream waits `compute_done[slot]` (previous consumer of that slot) → stages (register or slab) → `hipMemcpyAsync(d_w[slot])` → `copy_done[slot]`; compute stream waits `copy_done[slot]` → kernel on `compute_stream` → `compute_done[slot]`. Slot overwrite-while-reading is impossible; the double buffer overlaps slot B's copy with slot A's kernel (measured in `overlap.log`).
- ✅ Slab fallback race closed: before overwriting the pinned slab, `hipEventSynchronize(copy_done[slot])` waits for the previous H2D from that slab; slab growth frees only after that sync.
- ✅ Registration pairing: `hipHostRegister` spans are unregistered at layer end after the boundary sync and by the RAII `LayerGuard` on exceptions (the `LayerGuard` itself is `try/catch`-guarded).
- ✅ Exit: `layer_out_ready` recorded after the final residual kernel; the D2H on the copy stream waits it; exactly one `hipStreamSynchronize(copy_stream)` per layer call (line 1019; the other sync sites are realloc/exception/destructor drains only).
- ✅ Cross-layer safety: the next layer's H2D into `d_x` is ordered after the previous layer's `layer_out_ready` on the same copy stream; boundary sync drains everything between layers.
- ✅ KV pool: `release()` device-syncs before `hipFree` (its D2D writes land on the compute stream).

## 3. Findings

| QAQC-7E-1 | ◐ Low (latent, not reproduced) | `~DeviceLayerWorkspace()` calls `drain()` and `~DeviceKVCachePool()` calls `release()` **unguarded**, and both use `HIP_CHECK` (throws). If the HIP context is already torn down at static-destruction time, the throw escapes a destructor → `std::terminate`. Probed on this host (forward + exit without `kv_cache_free`): exit code 0 — the context is still alive at that point, so not a crash here, but it is order-dependent. Suggested (optional) hardening for a later package: wrap destructor drains in `try/catch` like the existing `LayerGuard`.
