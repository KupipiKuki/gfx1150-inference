## 2. Conditions / carry-forwards

### C-G1-1 (P0) — BLOCKER-7A4-1 must be fixed in a new `src/` package

The 7A-4 fuzz found a real parser defect: a metadata array whose element type is
`ARRAY` recurses, so a ~12 KiB hostile header raises `RecursionError` (and below the
threshold the invalid file is accepted). The parser is **not yet fail-closed** for this
class. The defect is minimized, hash-pinned, and covered by a strict xfail; the fix
(reject `ARRAY` as an element type) belongs in a new `src/gguf_parser.py` package.

**Release rule:** do not claim a fail-closed parser until C-G1-1 lands. The pinned strict
xfail is the acceptance criterion. This does not invalidate G1 (test infrastructure), but
it is a P0 before G6/v0.7.0.

### C-G1-2 (Minor) — public claim correction

`IMPLEMENTATION_PLAN.md` Phase 6 claimed “truncated or malformed GGUF files raise
`ValueError`” without the nested-array exception. The claim is now qualified inline with
the BLOCKER-7A4-1 limitation. The QF-1 wording in `BLOCKER.md` (“every caller catches
`ValueError`”) should be softened in the fix package.

### C-G1-3 (Carried, not a G1 failure) — GPU CI

7A-7 is accepted as a scaffold, not as enforced GPU coverage. 7F-1 must register the
self-hosted `gfx1150/rocm` runner, remove `continue-on-error`, and require 18 passed /
0 skipped. Until then, the GPU lane is queued-not-green and must not be counted as a G1
pass.

### C-G1-4 (Carried to 7B/7C) — tokenizer goldens

The 7A-3 goldens pin four known tokenizer mismatches with `xfail(strict=True)`
(`add_bos` default, special-token encode, SPM contraction segmentation, SPM parsed
control token). 7B/7C must turn these green or explicitly narrow the supported tokenizer
scope; the strict xfails prevent silent acceptance.
