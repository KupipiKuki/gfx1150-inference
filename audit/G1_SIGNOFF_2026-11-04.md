## 2. Conditions / carry-forwards

### C-G1-1 (P0) — BLOCKER-7A4-1 parser fix — **CLOSED 2026-11-04**

The 7A-4 fuzz found a real parser defect: a metadata array whose element type is
`ARRAY` recursed, so a ~12 KiB hostile header raised `RecursionError` (and below the
threshold the invalid file was accepted).

**Closure:** 7A-9 (`wp/7A-9-gguf-array-fix`, work commit `1bce3d0`, tip `9493cf8`)
added the element-type check in `GGUFParser._read_value` and removed the strict xfail.
Independent audit reproduced depths 1/2/5/300/992/1000/5000 raising `ValueError`, the
pinned 11,962-byte example (sha256 `28fe58bf…`), valid-array and pre-existing
malformed-class behaviour unchanged, CPU 111/24/4, GPU 24, and CI
`41954045892` + `41954045836` success. See
`audit/AUDIT_7A-9_PARSER_FIX_DEEP_2026-11-04.md`.

**Release rule (met):** the parser may now be described as fail-closed for every
malformed class the suite covers. This closes the G1 blocker; G6 still depends on the
later gates.

### C-G1-2 (Minor) — public claim correction — **CLOSED 2026-11-04**

`IMPLEMENTATION_PLAN.md`’s “truncated or malformed GGUF files raise `ValueError`” claim
no longer carries the nested-array exception, and `BLOCKER.md` §3.1 now states the
parser’s documented contract (asserted by the tests and followed by external consumers)
instead of “every caller in this repository catches `ValueError`”. The claim is honestly
scoped to the malformed classes the suite covers.

### C-G1-3 (Carried, not a G1 failure) — GPU CI

7A-7 is accepted as a scaffold, not as enforced GPU coverage. 7F-1 must register the
self-hosted `gfx1150/rocm` runner, remove `continue-on-error`, and require 18 passed /
0 skipped. Until then, the GPU lane is queued-not-green and must not be counted as a G1
pass.

### C-G1-4 (Carried to 7B/7C) — tokenizer goldens — **CLOSED 2026-11-06**

The 7A-3 goldens pinned four known tokenizer mismatches with `xfail(strict=True)`
(`add_bos` default, special-token encode, SPM contraction segmentation, SPM parsed
control token). The 7B remediation (`wp/7B-remediation` @ `1be1ad4`, work `25e9088`)
turned all four green, removed the strict xfails, and added a 310-case
reference-generated differential corpus plus 2,000-case independent differential; the
SPM path now matches the pinned llama.cpp greedy merge and `is_prev_special` prefix
behavior. See `audit/AUDIT_7B_REMEDIATION_DEEP_2026-11-06.md` and
`audit/G2_SIGNOFF_2026-11-06.md`.
